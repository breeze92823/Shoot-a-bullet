## The game
A lego-style lobby on an island, rebuilt from the owner's Roblox screenshots (North / South / West / training views):
- **Train**: stand on a plot's pad (the bracket square at its front) to shoot its dummy once per `ECONOMY.trainInterval`; each shot gives `baseRate * plot mult * gun mult * (1 + rebirths)` Damage (15% crits x2) with "+N Damage" popups and the GAMES / AUTO REBIRTH panel. Plots need rebirths (`TRAINERS`); the three premium plots need R$ and stay locked.
- **Shoot**: on the yellow SHOOT ZONE pad press SHOOT (HUD button, or F / E / Enter). A short cinematic plays: over-the-shoulder aim, muzzle blast, then the camera rides the flaming bullet down the smash range: a long table with `ZONES.length` x `RANGE.perZone` (9 x 20 = 180) breakable objects in themed zones (Targets, Slime, Squishy, Cardboard, Wood, Ice, Brick, Steel, Diamond). It smashes every object whose `need(i)` (`SMASH`) your Damage reaches, each paying `wins(i)`, and sticks in the first one it can't break ("STUCK IN <ZONE>!" + total Wins), then cuts back under a white flash. 53.1K Damage = 89 smashed, about 3.2K Wins. The HUD shows letterbox bars, "+N WINS" / "N / 180 SMASHED" and a styled banner per zone.
- **Gun Shop** (west): walk onto a pad to buy (Wins) or equip a gun; the gun multiplies training. **Rebirth** (Rebirth window) at the max LEVEL resets Damage for +1 multiplier and raises the max LEVEL by 10 (10 -> 20 -> 30...; the `ECONOMY.levels` curve is stretched over the extra levels, so the damage needed per rebirth is unchanged).
- **Evolve Ammo** (Evolve window): spend Wins to move up the `AMMO` tiers; each multiplies the Wins a Shoot Zone bullet pays and recolours the flying bullet.
- **Playtime Gifts** (Rewards tile): 8 `PLAYTIME_GIFTS` cards unlock by play time this visit (they reset each visit): Wins, or 2x boosts (`BOOSTS`: speed, jump height, Wins, Damage) shown as timer chips under the 2X passes.
- Robux buttons (Auto Wins, 2X passes, +100K/+1M/+10M, Auto Rebirth, premium plots) only show a "not connected" toast.

Three.js (vanilla, no React) + Vite + Rapier (`@dimforge/rapier3d-compat`, wasm inlined; `main.js` awaits its init at top level, hence `build.target: 'es2022'`). Everything is procedural (canvas textures); the only imported model is the Bloxity base rig `public/avatars/player.glb`. Fonts: Lilita One (HUD and world signs) and Fredoka, loaded in `index.html`. Tone mapping is Neutral (keeps the lego colours saturated; ACES greyed them).

- `npm run dev` / `npm run build`. `VITE_DEV_MODE=true` (see `.env.example`) skips the Bloxity SDK/CDN. Deploy: `.github/workflows/deploy.yml` uploads `dist/` to Bloxity Hosting (main = prod, dev = dev channel).
- All tunables are in `src/config.js` (the rest of `src/` holds no theme values). It now has: identity (`GAME_SLUG`, `GAME_TITLE`, `DEV_MODE`), the world (`WATER`, `SPAWN`, `SPAWN_FACING`), `MODES`, `PHYSICS`, `PLAYER_DIMS`, the look (`RENDER`, `FOG`, `TIME_OF_DAY`, `LIGHT`, `CHARACTER_COLORS`, `MATERIAL_PBR`, `GRAPHICS_PRESETS`, `BLOOM`, `NEON`, `graphicsPreset`), `TOUCH`, `CAMERA`, `SETTINGS`, and the rig (`RIG*`, `PROPORTIONS`, `ANIM`), plus the game: `STUD`, `CHECKER`, `PALETTE`, `ISLAND`, `PATHS`, `SPAWN_PAD`, `SHOOT_ZONE` (+ `fireAt`), `RANGE`, `SMASH`, `BULLET`, `ZONES`, `PLOT`, `TRAINERS`, `GUN_SHOP`, `GUNS`, `ECONOMY`, `PLAYTIME_GIFTS`, `BOOSTS`, `AMMO`, `AMMO_SKIP_ROBUX`, `NEW_WORLD_AT`, `NPCS`.
- All Bloxity SDK calls go through `src/bloxity.js` and must never throw (SDK may be blocked). It handles init/loading steps, auth (user/guest), settings (`graphics_quality`, `camera_sensitivity`, `show_fps`, `fullscreen`), avatar + proportion change events, the portal `respawn_request` event, the avatar customizer, and the matchmaker helpers the future net layer needs (`resolveServerEndpoint`, `locateRoom`, `updateRoom`).

## Files (`src/`)
- `main.js`: boot order = Bloxity SDK -> renderer -> Rapier -> sea + clouds, lighting, lobby + colliders, player body, HUD, shooters -> avatar (async, swaps in when ready) -> loop (physics, interpolate player, avatar animator, camera, sea ripples, lighting, bloom render). `__game` (dev only) exposes `player`, `scene`, `renderer`, `camera`, `postfx`, `lobby`, `particles`, `bodies`, `toggleMode`, `teleport(x, y, z, facing)` (facing `Math.PI` = north, -Z) and `stats.get()` / `stats.set({...})` (`set({ damage: 43200, wins: 47 })` recreates the reference shots), `playtime(sec)` fast-forwards this visit's Playtime Gifts clock. Dev server: launch config `shoot-dev` in the parent folder (port 5231, `VITE_DEV_MODE=true`).
- **Player**: `player.js` kinematic capsule + Rapier `KinematicCharacterController` (autostep, slopes, snap-to-ground, pushes dynamic bodies), own gravity/jump (coyote time + buffer). Feet position is `player.position`; `player.renderPosition` is interpolated for drawing. Falling below `PHYSICS.killY` respawns. `camera.js` third-person chase cam (boom, wheel zoom, wall clearance via `segmentClear`, speed FOV) and first person at the inner zoom end; `modes.js` `character` (avatar visible) / `player` (first person, avatar hidden), V toggles. `input.js` keyboard / mouse / pointer lock into `inputState`; `touch.js` + `touch.css` touch controls.
- `avatar/`: `character.js` (player.glb or procedural fallback), `loader.js` (Bloxity cosmetics + proportions from the CDN, `cdn.js`), `rig.js` + `animator.js` (procedural idle/run/airborne/landing; tunables in `ANIM`).
- **Physics**: `physics.js` Rapier world, fixed 60 Hz step with an accumulator; dynamic meshes bound via `bindMesh`/`addDynamic` are interpolated between ticks. Static geometry uses `addFixed` / `addFixedBoxFor`. `segmentClear` is the camera's ray against static colliders only.
- **Lobby**: `lobby.js` `buildLobby(scene)` builds everything from studded bricks and bakes the static ones (`bake.js`) into one mesh per material: checker baseplate on a lavender slab, perimeter wall + invisible fences, `PATHS`, the Shoot Zone pavilion (pad, checker floor, roof, lamps, bollards, signs), the smash range (`range.js`), the `TRAINERS` plots (`plots.js`), the Gun Shop (`gunshop.js`), trees/bushes/flowers/rocks and the ??? countdown board. Returns `plots`, `shopPads`, `range`, `update`. `range.js` `buildRange`: the table, one checker platform + side walls + nested arch (with a lock sign of the zone's Damage) + decor per `ZONES` entry, the objects as one InstancedMesh per zone per material layer (`smash`, `stick`, `knock`, `resetAll` with a staggered pop-in), and pooled instanced debris chunks. `lego.js`: stud textures (`legoMat`, `checkerMat`), box geometry with stud-tiled UVs, `brick` / `span` (optionally solid; never solid inside a local group that is moved later). `signs.js`: outlined sign text with lock/trophy icons and pills, as sprites or planes. `plots.js`: one detailed plot per `TRAINERS` entry, built in plot units and scaled by `PLOT.scale` (plots are ~3 characters wide, dummies ~1.7 tall, as in the reference): segmented two-tone rim, corner blocks, walkway, two-tier pedestal, the training dummy, the pad with decal + neon frame, per-theme decor and ambient particles; colours in `PLOT_THEMES`. `gunshop.js`: the two-tier plaza at its real footprint (pads ~2 m, ~3.5 m apart), stairs with cheek walls, the framed GUN SHOP board, layered glowing pads with light tubes and fitted, tilted guns. `lobbykit.js`: shared painters and props (fade/pad/glow textures, animated water `pool`, `flame`, trees, pines, crystals, crates, barrels, coins, lanterns, seaweed, coral, gems, `edgeFrame`). `guns.js`: one builder per weapon (pistol, magnum, uzi, mp5, vector, ak, scar, shotgun, lmg, sniper) with sights, rails, mags, stocks, scopes; each gun is baked to one mesh per material (`makeGun`, muzzle in `userData.muzzle`). `world.js` is now only the sea and the clouds.
- **Frame order matters**: `main.js` calls `applyAim` (aim pose + recoil) BEFORE `shooting.update`, so every muzzle read sees the arm where it is drawn (reading it first gave the hand-down idle pose: bullets and tracers started a metre below the gun).
- **Game**: `game.js` stats (damage, wins, rebirths, guns, ammo), save/load, levels (`maxLevel`), rebirth, `shotResult` (x rebirth x `winsMult` = ammo x Wins boost), ammo evolve, Playtime Gifts + boost timers (per visit, not saved; `player.speedMult` / `jumpMult` follow them), `fmt`. `shooting.js`: hand-mounted gun + aim pose (`attachToHand` caches the mount per avatar from its bind pose, `applyAim` runs after the animator), training shots, NPC shooters, per-gun muzzle effects (`muzzleFx`: flash star + flame tongue along the barrel, flash light, smoke, an ejected casing that bounces with a tink, arm recoil; all sized by `GUN_FX[GUN_SOUND[kind]]`), tracers, and the shot cinematic (`requestShot`; phases aim -> fly -> stuck -> back; the aim camera frames the gun from behind its grip, then after the trigger the round leaves the barrel in slow motion (`BULLET.exitTime` / `exitSpeed`, its fire builds with speed) while the camera swings in beside it and glides into the bullet cam; the outlined flaming bullet, fire trail, speed streaks, smash calls, `applyCamera` after the chase cam). The HUD gets each beat through `ctx.cine` (`hud.cine`); `hooks.hold` / `release` snap and freeze the player (`player.frozen`). `particles.js`: one pooled additive Points system (sparkles, motes, sparks, trails, sea glints; `setBudget` follows the preset). `hud.js` + `hud.css`: the whole HUD, world-anchored popups and modals; `windows.css` + `renderWindow` draw the Playtime Gifts / Rebirth / Evolve Ammo windows from the owner's reference shots (sized in `--wu`, fits 360px portrait and phone landscape), Store / Games keep the plain list modal; sizes use `--u = min(1vh, 1.15vw)`; it stays out of Boxity's reserved rectangles and moves the training row under AUTO WINS on short screens.
- **Sound**: `audio.js` (+ `audio.css`), all synthesised, no files. One AudioContext started on the first gesture; one-shots are rendered once per variant with OfflineAudioContext (gunshots per `GUN_SOUND` class, a dummy thwack / crit ding, the big Shoot Zone blast + slide rack, one smash per `ZONES` kind, coins climbing a pentatonic run per smash, zone stinger, impact, fanfare / aww, cha-ching, swell, UI click / deny, rebirth, footsteps / jump / land, fire crackles, birds) and played with random pitch, pan, and distance attenuation + air absorption from the camera (`at`). Realtime layers: `flight` (air rush + fire roar following the bullet's speed) and the ambience (sea swell, foam, wind; birds by day; ducks during the shot). Buses sfx / ui / amb -> master -> glue comp -> limiter, plus a generated-impulse reverb send. Every HUD button press clicks (capture listener). Mute: M or the speaker button (top right), saved. Tunables in `AUDIO`; `audioDebug()` shows the bank and play counts.
- **Sky and light**: `lighting.js` sky shader, stars, PMREM environment, shadowed sun following the player, fog, day/night blend (N). `addLamp` lights the pavilion lamps at night; `setMoods(sky)` is unused. `postfx.js` bloom (EffectComposer: HDR half-float render -> UnrealBloomPass -> OutputPass), on for the High/Ultra presets only (`BLOOM`; threshold 2.0 so sunlit surfaces never bloom).
- **Materials and textures**: `textures.js` canvas painters (cracked sand, water ripples, grass/tiles/crates/planks, outlined text, soft dots, sparkles, ...) and `toTexture` / `mulberry32`. `propkit.js` shared prop helpers: `std`, `glow`, `neon(color, k)` (unlit, HDR-bright with bloom; switched by `setNeonBloom`), `put`, `solidBox` / `solidPole` colliders, `label` (outlined text sprite, repainted once Fredoka loads). `bake.js` merges a Group's static meshes to one mesh per material (the lobby uses it).
- Controls: WASD/arrows, Shift sprint, Space jump, F / E / Enter shoot (on the pad), M mute, mouse look (click grabs the cursor = pointer lock, Esc releases it, then Esc opens the portal menu), wheel zoom, V mode, N day/night, R respawn. Never bind P (CrazyGames: Boxity's pause menu).
- Graphics: `graphicsPreset(name)` in config resolves the preset; on coarse pointers the default is Medium and every preset is capped by `MOBILE_GRAPHICS_CAP` (DPR 1.5, 1024 shadow map, no bloom), because the Bloxity SDK sends `High` itself.
- Boxity layout (required to publish, docs.bloxity.io Platform UI rules): Boxity draws the menu / pause menu, chat, emotes, avatar editor, invite, leaderboard and sign-in itself in a toolbar in the top-left corner with the chat feed under it, so the game never draws those buttons and keeps any HUD out of those rectangles (`bloxity.onReservedAreas`).

## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.
